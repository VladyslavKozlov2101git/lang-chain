# 001 — Задачі

Порядок має значення: кожна задача спирається на попередні. Жодна не вважається
зробленою без свого тесту, і номер AC стоїть у назві тесту.

- [x] **T1 — Каркас.** `package.json` (ESM, Jest 30 з `--experimental-vm-modules`),
      депенденси: `@langchain/core`, `@langchain/openai`, `@langchain/langgraph`,
      `@langchain/langgraph-checkpoint-sqlite`, `exceljs`, `zod`, `jest`. Драйвер БД — вбудований
      `node:sqlite`, нативного `better-sqlite3` у прямих залежностях немає.
      Скрипти `test`, `seed`, `intake`, `review`.
      → закриває частину **AC-30** (порожній `npm test` проходить)

- [x] **T2 — БД і seed.** `src/db.mjs`: схема з plan.md, міграція на старті, `npm run seed`, шим `node:sqlite` під
      офіційний `SqliteSaver` (+ тест на put/getTuple/putWrites, бо тихий злам шима ламає resume).
      `seed/`: 3 магазини, 3 постачальники, ~40 SKU із кратностями, ставками ПДВ 20/14%
      і мін. залишковим терміном, 6 заявок із рядками.
      → тест: seed проганяється двічі й дає той самий стан

- [x] **T3 — Гроші й нормалізація.** Парсер копійок (`45,80` / `45.80` / `45 грн 80 коп`),
      нормалізатор назв товарів (регістр, пробіли, одиниці, `,`↔`.` у числах).
      → **AC-4**

- [x] **T4 — `validate.mjs`.** Чиста функція, R1–R10, ПДВ-конверсія, коди причин.
      Перший справжній обсяг логіки — і перший справжній обсяг тестів.
      → **AC-9 … AC-18**

- [x] **T5 — Інтейк.** `src/intake.mjs`: txt і xlsx → raw, `sha256`, `thread_id`.
      Фікстури: 12 документів за таблицею зі spec (назва файлу = правило, яке він ламає).
      → **AC-1**, **AC-25** (хеш однаковий на той самий вміст)

- [x] **T6 — LLM-обв'язка.** `src/llm.mjs` — перенести з гілки `node`: ключ із
      `auth.json`, хедер `x-opencode-session`, вибір моделі через env.
      → тест: фабрика віддає модель і не стукає в мережу на етапі створення

- [x] **T7 — `extract.mjs`.** Промпт, zod-схема, ретрай із текстом помилки, ліміт 2,
      розпізнавання магазину-отримувача.
      → **AC-2**, **AC-3**

- [x] **T8 — `match.mjs`.** Шортліст top-5, вибір через LLM із confidence, перевірка що
      вибір у межах шортліста, читання алясів, запис алясів (виклик з `review`).
      → **AC-5 … AC-8**

- [x] **T9 — Граф.** `src/graph.mjs`: вісім вузлів, ретрай-ребро, умовне ребро `route`,
      `interrupt()` у `review`, `SqliteSaver`. Фабрика приймає `{ model, db }`.
      → **AC-19**, **AC-20**, **AC-27**

- [x] **T10 — Коміт і акт.** Транзакція `receipt` + `receipt_line`, UNIQUE-конфлікт →
      `duplicate`. Акт розбіжностей і часткове приймання. Вузол `explain`.
      → **AC-21 … AC-24**, **AC-26**

- [x] **T11 — CLI.** `intake` / `review` / `resume`, таблиця розбіжностей, друк команди
      відновлення після падіння.
      → **AC-28** (інший процес бачить тред), **AC-29**

- [x] **T12 — README.** Запуск, env, що в скоупі й чого немає. Коротко.

- [x] **T13 — Eval із повторами.** `npm run eval -- -r N`: золоті відповіді на всі 12
      фікстур, офлайн-перевірка самих золотих даних, метрики по хедеру, рядках і SKU.
      Окремо виведений найдорожчий клас помилок — не той SKU при впевненості ≥ 0.8.

      **Замір 2026-10-21, `deepseek-v4.1-flash`, 60 прогонів (12 × 5):** витяг з першої
      спроби 100%, ретраїв 0, хедер 100%, рядки 100%, SKU 100%, тихих помилок 0.
      Медіана 6,8–15,5 с на документ.

      Що це доводить: на вході **такої форми** модель не має грубої нестабільності —
      з 60 спостережень і 0 збоїв верхня межа частоти збою ≈5% (95% впевненості).
      Чого не доводить: нічого про реальні листи. Усі 12 фікстур написані однією рукою
      в одному стилі, тому міряна була стабільність моделі на фіксованому вході, а не
      різноманіття входу — а в продакшені ламає саме друге.

      Найсильніша цифра заміру: **215 з 215** рішень матчингу правильні, аляси вимкнені.
      Серед них 35 разів модель відрізнила «Сметана 20% 350 г» від «Сметана 15% 180 г»
      і стільки ж разів сир 9% 350 г від 5% 180 г — саме ті пари, помилка в яких
      проходить усі десять правил тихо.

- [x] **T14 — Локальний фронт і трасування.** `npm run web`: `node:http` + одна
      HTML-сторінка, нуль депенденсів. Таблиця розбіжностей із галочками, ланцюг вузлів,
      кожен виклик моделі розгортається. `trace.mjs` — обгортка моделі, звідси ж `--trace`
      у CLI.

- [x] **T15 — Примітки постачальника.** `note` на рівні документа й рядка: витяг,
      блок рішень (CLI і фронт), лист-відповідь. Оригінал листа віддається разом
      із тредом.
      → **AC-31**

      Дірка знайдена не тестами, а очима: у листі було написано «поклали ящик нового
      йогурта **на пробу**, ціна протокольна», а в блок рішень доїхало сухе «позиції
      немає в заявці». Формально система права, по суті — створює роботу з нічого:
      людина мусить іти перечитувати оригінал, щоб зрозуміти, що це не помилка.

      Межа навмисна: примітка пояснює, але не погоджує. R9 спрацьовує так само, і в
      промпті листа-відповіді прямо сказано, що ціну погоджують протоколом, а не листом.
